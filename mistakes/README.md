# 开发错题与防呆

- modinfo 在原生受限元数据环境执行，不能假设 ipairs 等标准全局可用；四种语言均应做加载检查。
- 官方上传器要求更新版本号；发布后回读版本及实际下载文件，不能只看成功提示。
- 游戏控制台指令可能截断，尽量小于 450 字符；异步诊断使用已初始化局部闭包变量，避免 strict.lua 的未声明全局错误。
- 不直接修改 Steam 管理的订阅目录作为唯一源码；保留 Git 基线和发布清单。
- DST 的 prefab `OnSave(inst, data)` 必须填写传入的 `data`，不能照搬组件 `OnSave()` 返回表的约定。制冰初版曾在模拟中漏检，原生 `GetSaveRecord` 回读发现归属／进度未存；已改成写入 data，并增加原生 `SpawnSaveRecord` 恢复检查。模拟桩必须遵循真实接口签名。
- `workable:SetWorkLeft` 会同时启用采矿；读档后等待跨分片额度确认时，必须再次 `SetWorkable(false)`。保存原始 `workleft`，避免把暂时不可采误存为零。
- 原版 `container:SetNumSlots` 不允许运行中重设已初始化的容器。旧背包测试应恢复仅包含旧槽位的真实存档数据，而非修改运行时格数；1.3.5 首轮测试夹具因此断言，生产代码未调用该重设。
- 原版 `Map:GetPlatformAtPoint` 签名为 `(x,z)`，不是 `(x,y,z)`；剑气旧逻辑曾错误传入三参，1.3.5 修正并增加签名回归。
- 仅修改 `combat.min_attack_period` 不能突破原版攻击状态的最低时长（角色剑为 13 帧）。攻速需同时验证攻击时间线与真实连续攻击，不能只测字段。

新增错题记录：触发条件、根因、修复办法、防复发检查、验证边界。

- 岸边搜索原在检查 24 个不满足放置条件的临水点后提前返回，卍解范围内更远的空地可能被漏掉。用半径 20、近岸拥挤而远岸空闲的场景复现失败后，改为遍历原有有限候选网格（普通最多 80、卍解最多 316）。不放宽原生碰撞／海岸／洞穴安全条件，不修改冷却或数量规则。隔离回归通过不代表用户现场地形已经验证；最坏情况空间查询次数增加，尚未做多人密集场景性能压测。

- 工坊目录的 `mod.manifest` 是文件索引，不随本地新增 Lua 自动扩展。1.3.5 原生独立本地 Mod 测试通过，但真实工坊加载报 `module 'hitsugaya_ice' not found`，即使磁盘文件存在、哈希正确。使用原版支持的 `modinfo.forcemanifest=false` 供本地开发测试，补充带 `-ugc_directory` 的真实工坊加载验证；正式上传时仍由官方上传器生成完整索引。不能将本地 Mod 测试等同于工坊挂载验证。
